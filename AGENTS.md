# Работа с Recall

- По указанию владельца все согласованные изменения собираются в `main`,
  коммитятся, пушатся и выкатываются целиком. Отдельные ветки и черновики PR
  не заменяют публикацию в `main`, если владелец явно не попросил такой процесс.
- Перед публикацией выполнить `pytest` для полного текущего набора изменений.
- Рабочий бот: Railway, проект `recall-bot`
  (`a5b6a86c-03a4-4eed-a11d-a8b8832a666b`), сервис `recall-bot`
  (`3e025a63-8ac8-44e6-a577-5ded3b170630`), окружение `production`.
- Перед обновлением рабочей базы сделать согласованную SQLite backup-копию
  на постоянном томе и проверить её целостность. Сохранять идентификаторы слов,
  карточки, историю ответов и расписание повторений.
- После выкладки дождаться `SUCCESS` именно у отправленной версии, проверить
  запуск polling, миграции, актуальность словаря и сохранность данных. Загрузка
  исходников сама по себе не означает успешную выкладку.
- После операций с инфраструктурой обновить `../general/ops/journal.md`.
