# recall_bot

Telegram-бот для изучения английских слов методом интервальных повторений (SRS на базе FSRS).

## Что умеет

- Показывает русский перевод — пользователь вводит английское слово.
- Обратное направление: показывает английское слово — пользователь вводит один русский перевод.
- Английский проверяется строго: case-insensitive, но Levenshtein > 0 = ошибка.
  В обратном направлении принимается один из словарных переводов с учётом частей
  речи; регистр, лишние пробелы, конечные `. ! ?` и различие `е/ё` не влияют на оценку.
- Карточки: `new → learning → review → graduated`. После 5 успехов подряд при интервале ≥30д слово считается выученным.
- Батчи новых слов выдаются по `frequency_rank`. Автоматически новый батч открывается, когда все слова текущего перешли в `review` (т.е. первый интервал успешно пройден).
- Ежедневные напоминания в указанное пользователем время и часовой пояс.
- Одно-два примера употребления каждого слова после ответа или «Не знаю».
- Учитывает ещё не освоенные английские слова в групповой переписке и отмечает практику короткой похвалой.

## Команды

- `/start` — онбординг: начать с самых частотных или пропустить N слов.
- `/learn` — занятие: due-карточки + новые из всех начатых батчей (по `daily_goal`).
- `/reverse` — то же занятие в направлении английский → русский.
- `/more [N]` — добавить новую порцию слов и сразу начать её изучение. Без числа берётся размер батча из настроек, с числом — от 1 до 500 слов. Доступна также кнопка «Ещё слова» после занятия и когда нет повторений.
- `/cram [N]` — форсированная сессия из N новых слов (default 50, max 500).
  Игнорирует обычные ограничения батча/daily_goal. Подходит когда хочешь
  быстро прощёлкать знакомые слова. Старый «залипший» батч не теряется —
  неоткрытые карточки доступны в `/learn`, повторения сохраняют свой интервал.
- `/stats` — сегодня / в изучении / на повторении / выучено / CEFR.
- `/settings` — части речи, размер батча, время напоминания, часовой пояс.
- `/help` — подсказка по всем командам и кнопкам.

При запуске бот регистрирует меню команд Telegram на русском и английском. Команды доступны по `/` и через кнопку меню.

В карточке две inline-кнопки:
- 🤔 **Не знаю** — раскрывает ответ, засчитывает как ошибку (FSRS вернёт в learning), переходит к следующей.
- ⏭ **Пропустить** — откладывает до завтра без оценки.

### Обратный перевод

В `/reverse` достаточно одного русского значения из словаря: например, для
`light` — «свет» или «лёгкий», если обе части речи выбраны. После ответа показываются
все допустимые переводы и примеры. Фильтр частей речи и категории, сохранённые
у карточки при выдаче, действуют и при проверке русского ответа.

Значения в словаре разделены точкой с запятой. Пояснение в скобках можно опустить:
«удар (кулаком)» принимается и как «удар»; «собирать(ся)» — как «собирать» или
«собираться». Запятая внутри выражения сохраняется. Неизвестные словарю синонимы,
опечатки и части слова не засчитываются.

Оба направления используют те же карточки, историю, FSRS и статистику.
Отдельного расписания для обратного перевода нет. Кнопки **Продолжить** и
**Ещё слова**, а также `/more` и `/cram`, сохраняют направление текущего занятия.
`/learn` возвращает перевод на английский, `/reverse` включает перевод на русский.
После перезапуска бота новое занятие по `/more` начинается с обычного направления.

### Выбор частей речи

`/settings` → **Части речи**. По умолчанию включены все категории. Нажатие
категории в режиме «Все» выбирает только её; следующие нажатия добавляют или
убирают категории (логика ИЛИ). Кнопка **Все части речи** возвращает весь словарь.
Выбор сохраняется сразу в SQLite; убрать последнюю категорию нельзя.

Счётчик показывает **оставшиеся новые слова** после стартового уровня пользователя,
исключая слова, для которых карточка уже была выдана. Одно слово с несколькими
подходящими значениями считается один раз. Выдача `/more`, `/cram` и автоматических
порций использует то же условие. При смене выбора ранее пропущенные фильтром
частотные слова снова доступны; уже выданные карточки не дублируются.

Фильтр действует также на неоткрытые карточки и запланированные повторения в
`/learn`. Неподходящие карточки скрываются, сохраняя FSRS, даты, историю и прогресс.
При возврате категории они снова доступны, с учётом прежней даты повторения и
отложенных до завтра слов. Новая карточка запоминает категории, с которыми её
выдали: карточка существительного не превращается в глагол после смены настроек.
Статистика продолжает учитывать весь сохранённый прогресс.

Фильтруется **русский перевод конкретного значения**, а не только английское
написание или общая метка строки. Например, у `back` в режиме существительных
показывается «спина», а в режиме наречий — «назад», без смешивания этих значений.
Модальные и фразовые глаголы включены в «Глаголы». Для непроверенных значений и
неизвестных меток есть **Прочее / без разметки**, включённое в режим «Все».

## Статистика в групповых чатах

Добавь Recall в группу и отправь `/challenge@recall_english_bot`. Организатор
попадёт в таблицу первым; остальные вступают кнопкой **Вступить** или `/join`.
Обучение остаётся в личном чате с ботом. Кнопка **Открыть бота** ведёт туда,
без Mini App. Сам переход по ссылке не добавляет человека в таблицу.

Каждый вечер, по умолчанию в **21:00** по часовому поясу организатора
(для нового пользователя — Москва), бот публикует статистику участников:
**освоено всего** (состояния review + graduated) и **правильно сегодня**
(разные слова с верным ответом за день по часовому поясу группы).
Общий счёт включает прежнее обучение и не сбрасывается по неделям.

- `/leaders [страница]` или `/stats` — показать таблицу; **Обновить** и стрелки — обновить пост и перейти между страницами.
- `/leave` — выйти только из таблицы этого чата; личный прогресс сохраняется.
- `/settings 21:00 Europe/Moscow` — время и часовой пояс сводок.
- `/pause`, `/resume` — остановить и возобновить публикации.
- `/help_group` — правила и команды.

Расписание меняют организатор и администраторы группы. Участие и расписание
сохраняются в SQLite и восстанавливаются после перезапуска. При удалении бота
публикации останавливаются, при выходе участника он исключается из таблицы.
Для групп регистрируется отдельное меню команд. При включённом Privacy Mode
используй команды с `@recall_english_bot`; права администратора для обычной
работы не нужны, достаточно разрешения отправлять сообщения.

### Английский в групповой переписке

Если Telegram передаёт боту обычные сообщения группы, Recall замечает английские
слова в тексте и подписях к медиа у **всех зарегистрированных пользователей**.
Для этого не нужны `/challenge` или вступление в таблицу. Незарегистрированным
авторам бот не создаёт профиль и не отвечает. Личные ответы на карточки
обрабатываются обычным обучением.

Чтобы получать все сообщения, сделайте бота администратором группы либо
отключите Privacy Mode через BotFather; Telegram может потребовать заново
добавить бота после изменения настройки. При включённом Privacy Mode и без прав
администратора бот обрабатывает только те сообщения, которые Telegram ему
доставляет, например ответы на его сообщения.
[Правила Telegram](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

Порядок обработки:

1. Выделяются целые слова латиницей, в том числе внутри русских сообщений.
   Ссылки, адреса почты, упоминания, хештеги, код и оформленные цитаты исключаются.
   Пересланные, анонимные, отредактированные сообщения и сообщения других ботов
   не учитываются.
2. Слова сопоставляются со словарём Recall. Предлоги, артикли, местоимения,
   другие служебные слова и слова, размеченные как имена собственные, отбрасываются.
   `worked/working → work`, `children → child`, `studied → study` приводятся
   к леммам по проверенной таблице форм; приставки не обрезаются.
   Учитываются и смежные фразовые глаголы, например `gave up → give up`.
   Неоднозначные формы пропускаются, если простой контекст не позволяет
   выбрать одно слово. Это словарное распознавание, без проверки грамматики
   или доказательства правильного употребления конкретного значения.
3. В практику попадают карточки `new/learning` и ещё не выданные слова после
   стартового уровня пользователя. `review/graduated` считаются освоенными и
   не приносят новый зачёт практики. Карточки и FSRS от переписки не меняются.
4. Одно слово учитывается один раз за календарный день пользователя, даже в
   нескольких группах. Повторы обновлений также не дублируют запись.
   Похвала приходит ответом в тот же чат и тему, не чаще раза в 15 минут
   для одного человека в одном чате; остальные новые слова учитываются молча.

В личном `/stats` видны разные использованные слова сегодня и за всё время.
В групповой таблице добавлен отдельный счётчик практики за день группы, по всем
доступным боту группам; порядок мест по карточкам сохранён. Таблица по-прежнему
показывает только вступивших участников. `/leave` скрывает человека из таблицы,
а `/pause` приостанавливает вечерние сводки; эти команды не отключают распознавание
переписки зарегистрированных пользователей.

Бот сохраняет только идентификаторы пользователя, слова, чата и сообщения,
день, время и состояние освоения на момент употребления. Полный текст сообщения
не сохраняется и не отправляется во внешние сервисы. Практика и ограничение
похвалы переживают перезапуск.

[`data/dictionary_forms.csv`](data/dictionary_forms.csv) — формы английских слов
из Kaikki/Wiktionary, авторы — участники соответствующих английских статей
[`en.wiktionary.org/wiki/<english>`](https://en.wiktionary.org/), лицензия
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
Редкие, устаревшие, нестандартные формы и словообразовательные производные
не импортируются. Пересборка:

```bash
uv run python -m data.build_word_forms --kaikki kaikki.org-dictionary-English.jsonl.gz
```

## Стек

- Python 3.14, aiogram 3, pydantic-settings
- SQLAlchemy 2 (async) + SQLite через `aiosqlite`
- Alembic — версионированные миграции схемы
- FSRS (`fsrs` v6+) — алгоритм SRS
- APScheduler — ежедневные напоминания
- Docker Compose — локальный запуск

## Быстрый старт

### Локально (uv)

```bash
# 1) установить uv (если нет): https://docs.astral.sh/uv/
curl -LsSf https://astral.sh/uv/install.sh | sh

# 2) синк зависимостей и venv (~10 сек)
uv sync

# 3) запуск
cp .env.example .env       # вписать TOKEN
uv run python -m bot
# или
make run-local
```

При старте бот сам применяет миграции и, если таблица `words` пуста, засеивает
словарь из `data/dictionary.csv`. Отдельно ничего готовить не нужно — база
создастся файлом по пути из `DB_PATH` (по умолчанию `recall_bot.db` в корне).

Тесты:
```bash
make test                  # uv run pytest -v
```

### Через Docker

**Вариант А — стянуть готовый образ из GHCR:**

```bash
cp .env.example .env         # вписать TOKEN
# логин нужен, только если пакет приватный:
echo $GHCR_TOKEN | docker login ghcr.io -u <github-username> --password-stdin
docker compose pull          # тянет ghcr.io/romanychev-l/recall_bot/bot:latest
docker compose up -d
```

**Вариант Б — собрать образ локально из текущего кода:**

```bash
cp .env.example .env
docker compose up -d --build
```

База лежит на томе `bot_data` (внутри контейнера — `/data/recall_bot.db`) и
переживает пересоздание контейнера и обновление образа.

> ⚠️ **CSV запечён в образ.** `Dockerfile` копирует `data/` внутрь образа, поэтому
> автосид и `make seed-docker` используют тот `dictionary.csv`, что лежал в образе
> на момент сборки, а **не** твой локальный файл. После правки CSV пересобери образ
> (`docker compose up -d --build`) либо дождись нового образа из CI и `docker compose pull`.
> При старте пустая база заполняется словарём, а в существующей обновляются только
> частотные ранги совпавших английских слов. Для обновления переводов и добавления
> слов используй `make seed-docker` (апсёрт по английскому слову).

### Примеры употребления

У всех 20 070 записей в `dictionary.csv` заполнено поле `example`: одно или два
английских предложения либо коротких контекста, разделённых переводом строки
внутри CSV-ячейки. Они показываются в том же сообщении, что и результат проверки,
при верном/неверном ответе и после «Не знаю». До ответа примеры скрыты.
Для добавленных вручную слов без примеров обучение работает как прежде.

При запуске на существующей базе бот заполняет только пустые примеры, сопоставляя
слова по английскому написанию. Собственные примеры, переводы, части речи,
идентификаторы слов и весь прогресс обучения сохраняются. Повторный запуск
не переписывает уже заполненные примеры; миграция схемы не требуется.

Источники каждого примера, авторы и лицензии перечислены в
[`data/example_sources.csv`](data/example_sources.csv). Источники:

- [Tatoeba](https://tatoeba.org/en/downloads), предложения сообщества:
  [CC BY 2.0 FR](https://creativecommons.org/licenses/by/2.0/fr/) или
  [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/), согласно записи.
  Для CC BY указан автор из экспорта; ссылка ведёт к оригинальному предложению.
- Английский Wiktionary, авторы — участники соответствующей статьи:
  [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). Данные извлечены
  из локального [Kaikki/Wiktextract](https://kaikki.org/dictionary/English/) дампа.
  Импортируются только собственные usage examples участников, без цитат из книг
  и новостей; ссылки на статьи сохранены в таблице источников. Эти примеры
  распространяются на условиях CC BY-SA 4.0, отдельно от лицензии кода.
- [`data/authored_examples.csv`](data/authored_examples.csv): примеры Recall,
  включая дополнения для редких слов и имён, доступны на условиях CC0 1.0.

Тексты источников сохранены с нормализацией пробелов. Подбор автоматический:
предпочитаются короткие контексты с частотной лексикой, повторы отбрасываются.
Для многозначных слов примеры иллюстрируют употребление английского слова;
они не привязаны к отдельному русскому значению или фильтру частей речи.

Воспроизвести заполнение после пересборки словаря (экспорты скачиваются отдельно):

```bash
uv run python -m data.build_examples \
  --kaikki kaikki.org-dictionary-English.jsonl.gz \
  --tatoeba data/.cache/eng_sentences_detailed.tsv.bz2 \
  --cc0 data/.cache/eng_sentences_CC0.tsv.bz2
```

Сборка отклоняется до записи, если хотя бы одно слово осталось без примера.

### Значения и части речи

`data/dictionary_senses.csv` дополняет его разметкой каждого русского перевода:
`english,translation,parts_of_speech` (несколько категорий разделены `|`).
Разметка получена точным сопоставлением переводов с локальным Kaikki/Wiktionary
дампом; неоднозначность сохраняется, несовпавшие переводы помечаются `other`.
Ранги, идентификаторы и исходный словарь остаются прежними. При старте недостающая
разметка загружается в `word_senses`, в том числе на существующей базе; повторный
запуск не переписывает данные. Для своего CSV используется соседний
`<имя>_senses.csv`; без него доверяем указанной в CSV части речи, пустые и
неизвестные метки относятся к `other`.

После пересборки словаря с Kaikki пересобери и разметку:

```bash
uv run python -m data.build_word_senses --kaikki kaikki.org-dictionary-English.jsonl.gz
```

В репозиторий уже добавлены:

- `data/fixtures/test_words.csv` — 50 слов для smoke-теста.
- `data/phrasal_verbs.csv` — стартовый набор фразовых глаголов, легко расширить до 500.
- `data/easy_english_expressions.csv` — 1165 разговорных выражений и идиом из подкаста *Daily Easy English* (Coach Shane), `frequency_rank` 30001+.
- `data/basic_english.csv` — 847 слов из Basic English Ч.К. Огдена (100 операций, 600 существительных, 150 прилагательных). Эти же слова включены в `dictionary.csv` и занимают места по частотности, без отдельного приоритета.

Залить дополнительный набор в БД:

```bash
python -m data.seed data/easy_english_expressions.csv
```

### Пересев после переранжирования

`frequency_rank` — место слова среди включённых в словарь слов по убыванию
частоты в OpenSubtitles 2018, а `frequency_count` — число вхождений в исходном
[FrequencyWords](https://github.com/hermitdave/FrequencyWords/blob/master/content/2018/en/en_full.txt).
Это частотность разговорной речи в субтитрах, а не оценка сложности слова.
Фразовые глаголы идут после отдельных слов в порядке своего набора.

Чтобы исправить порядок, сохранив проверенные переводы:

```bash
uv run python -m data.rank_dictionary --frequency data/.cache/en_full.txt
```

При следующем запуске бот транзакционно перенесёт ранги по **английскому слову**,
сохранит `words.id`, карточки, историю ответов и расписание FSRS и обновит копии
рангов в карточках. Загрузка через `make seed-full` также сопоставляет слова по
английскому тексту. Дубликаты слов/рангов и конфликты с отдельными пользовательскими
наборами отклоняются до записи. Слова, которых нет в CSV, не удаляются.

Новые порции выбираются из ещё не выданных слов после стартового уровня по
актуальному рангу. Старый указатель следующей порции не может скрыть частотное
слово после изменения порядка. Очистка таблицы `words` для переранжирования
не требуется: она удаляет связанные карточки через `ON DELETE CASCADE`.

Для сборки полного словаря на 20 000+ записей из открытых источников:

```bash
make build-dict
```

Скрипт `data/build_dictionary.py`:
1. Качает [hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords) (OpenSubtitles, en).
2. Ждёт ~1.5 GB JSONL Wiktextract-дамп с [kaikki.org](https://kaikki.org/dictionary/English/index.html) (его нужно скачать руками в `data/.cache/kaikki.jsonl.gz`).
3. Сшивает английские леммы с русскими переводами, добавляет phrasal verbs.

> COCA / Routledge — проприетарные. Здесь использованы CC-BY-SA источники.

## SRS

Использует `fsrs` 6.x. `Scheduler(learning_steps=(1d,))` даёт типичную траекторию:

```
rep 1 (Good) → state Review, interval ~2 дня
rep 2 (Good) → ~9 дней
rep 3 (Good) → ~43 дня
rep 4–5 (Good) → продолжает расти
```

Поверх FSRS-состояния (`Learning / Review / Relearning`) лежит наша 4-state модель:

- `new` — карточка только что выдана, не отвечалась.
- `learning` — отвечалась, FSRS в Learning/Relearning. Lapse тоже сюда.
- `review` — FSRS Review.
- `graduated` — review + 5 успехов подряд + интервал ≥30 дней. Терминальная метка, дальше FSRS продолжает планировать.

## База данных

SQLite-файл по пути `DB_PATH`. Таблицы обучения: `users`, `words`, `word_senses`,
`batches`, `user_cards`, `review_log`; групповые сводки используют `group_chats`
и `group_members`. В `users.pos_filter` сохраняется выбор категорий,
в `user_cards.study_pos_filter` — категории при выдаче карточки. Миграция добавляет
их в режиме «Все», сохраняя существующие карточки и интервалы повторений.
Практика переписки хранится отдельно в `chat_practice`, ограничение частоты
похвалы — в `chat_practice_praise`. Их миграция не переписывает таблицы обучения.

Два решения, которые стоит знать:

- **`user_cards.due` вынесен в отдельную колонку**, хотя полный FSRS-стейт лежит
  рядом в JSON-поле `fsrs`. Фильтровать и индексировать ключ *внутри* JSON — криво
  и по-разному работает на разных СУБД, а обычная колонка ведёт себя одинаково
  везде. Репозиторий синхронизирует их при каждой записи.
- **Все datetime хранятся через `UtcDateTime`** — свой `TypeDecorator`, который
  приводит значение к tz-aware UTC и на запись, и на чтение. У SQLite нет типа
  для даты, поэтому tz-aware значение вернулось бы naive, а смешение naive и aware
  как раз ломало ревью карточек раньше.

### Миграции

Бот сам прогоняет `alembic upgrade head` при старте, так что руками обычно ничего
не нужно. Для локальной работы со схемой:

```bash
make migrate                        # alembic upgrade head
make revision m="add streak column" # autogenerate новой миграции
```

Тест `tests/test_migrations.py` падает, если модели разъехались с миграциями.

### Переезд на Postgres

Слой БД спрятан за репозиториями, а SQLAlchemy генерирует SQL под нужный диалект,
поэтому смена движка — это установка `asyncpg` и одна переменная:

```
DATABASE_URL=postgresql+asyncpg://user:pass@host:5432/recall_bot
```

`DATABASE_URL` перекрывает `DB_PATH`. Данные переливаются `pgloader` или разовым
скриптом. Реально это нужно, только если появится несколько процессов, пишущих в
одну базу, — для одного бота SQLite с запасом хватает.

## CI

GitHub Actions (`.github/workflows/automation.yml`): прогон тестов на каждый push
и PR, затем — только для `main` — сборка образа и push в GHCR.

Образ в GHCR **не на пути деплоя**: Railway собирает из репозитория сам. Образ
лежит, чтобы бота можно было поднять где угодно ещё.

## Деплой на Railway

Бот — обычный worker без HTTP-порта. Нужен один always-on сервис и том под базу.

1. **Создать сервис.** railway.com → *New Project* → *Deploy from GitHub repo* →
   выбрать этот репозиторий. `railway.json` уже указывает собирать `Dockerfile`.
2. **Подключить том.** В сервисе → *Volumes* → добавить том с mount path `/data`.
   Лучше сделать это до первого деплоя: `DB_PATH` в образе указывает на
   `/data/recall_bot.db`, и без тома база пропадёт при следующем деплое.
3. **Задать переменные.** В *Variables*:

   | Переменная     | Значение                         |
   |----------------|----------------------------------|
   | `TOKEN`        | токен от @BotFather              |
   | `SCHEDULER_TZ` | например `Europe/Moscow`         |
   | `LOG_LEVEL`    | `INFO` (опционально)             |

   `DB_PATH` задавать не нужно — он уже `/data/recall_bot.db` из `Dockerfile`.
4. **Задеплоить и проверить логи.** На первом старте должно быть
   `migrations_applied`, затем `dictionary_seeded words=20070` и `Bot starting...`.
   Сид ~20k слов идёт несколько секунд и происходит один раз.

Дальше каждый push в `main` пересобирает и передеплоивает сервис.

> ⚠️ **Нельзя держать два инстанса на одном токене.** Telegram отдаёт
> `409 Conflict`, если по одному токену идёт long polling из двух мест. Перед
> запуском на Railway останови старый контейнер бота, где бы он ни крутился.

### Забрать базу с Railway

SQLite — один файл, так что база переносится копированием. Через
[Railway CLI](https://docs.railway.com/develop/cli):

```bash
railway ssh 'sqlite3 /data/recall_bot.db ".backup /data/snapshot.db"'
```

Снимать копию именно через `.backup`, а не `cp`: в WAL-режиме рядом лежат
`-wal`/`-shm`, и сырое копирование живого файла может дать неконсистентный снимок.
